# Architecture

`completed conversation → immutable originals → incremental Worker → immutable segments in stable Topic Families`

`host requests recall → local keyword / optional vector candidates → Selector → selected family originals → main answer`

Capture never calls the Selector. The Worker sees only new completed records and up to ten candidate families, retrieved across the existing card archive. Candidate discovery does not establish semantic identity: the Worker must decide whether this is the same real-world goal, a separate related goal, or a new goal. It covers each selected record exactly once and commits a validated batch atomically when the storage adapter supports it.

The Worker returns keyword cards, one explicit `{sequence, topicIndex, change}` assignment per supplied record, and optional grounded links between cards or to supplied old families. Links distinguish `same_event`, `related` and `separate`; each cites an exact excerpt of an assigned source record. The core checks source provenance, IDs and contradictions, derives family IDs and spans, and rejects missing, duplicate or foreign sequences and unused cards. It does not infer an event match from a shared word or a change verb. An exact quote is provenance evidence, not semantic proof. Names and identifiers should retain source spelling. Change labels are annotations, not truth or deletion instructions.

Cards are compact pointers to original records. The Worker groups continuing discussion and revisions while avoiding groups so broad that retrieval becomes noisy. Boundaries are approximate; extra or merged cards are not failures by themselves. Evaluation should measure exact-original recall and evidence cost under a fixed budget.

A frozen card means its batch segment has been indexed, not that its subject has ended. Later discussion can create another segment in the same family. Similarity may create a related-family link without merging. Old originals, cards and family scope are not rewritten. A mistaken family assignment is still possible, especially when the relevant family is absent from the bounded Worker shortlist.

Local BM25 searches both every immutable card and the original archive. An optional embedding adapter embeds each newly accepted card once and embeds a query at retrieval time; stored vectors are reused only with a matching provider/model identity and card text. Reciprocal-rank fusion combines keyword and vector ranks. Vector failures are reported and fall back to keywords without losing originals. This is extra indexing/query cost, not free semantic search. The native configuration currently uses keyword candidates; embedding injection is an SDK option.

Relevance controls priority. Recency, separated occurrences and record count can change a relevance score by at most 15% of its value; an irrelevant zero-score family stays at zero. The heuristic uses 60% recency (30-day exponential decay), 30% capped log occurrence count and 10% capped log record count. A gap of 30 minutes between segments approximates recurrence; batch boundaries alone do not count, and elapsed span length receives no bonus. These constants are not a proven optimum or a confidence score.

The Selector sees at most twelve candidate families per page and selects at most three. A family card samples its earliest/latest segments and up to two keyword matches; it is not an exhaustive summary. If a query may need linked context, the Selector can request one-hop related-family expansion using remaining selection slots. Omitted linked IDs remain visible in the trace and prevent a completeness claim. If uncertain, the Selector can inspect selected originals in a second request. A selected family that exceeds the evidence budget can start at a locally matched original; explicit first/latest questions favor the first/last strong match. Long original-versus-revised comparisons receive bounded windows from both ends. `unreadPrefix` reports records skipped before a page in its chosen order. `memory_open` with offset 0 still reads the whole family in order, and `nextOffset` continues an evidence page. For heavily interleaved families, redundant span metadata may be omitted and flagged; each returned original still has its own sequence and timestamps. Remaining candidate pages stay available even without lexical overlap; an incomplete search cannot establish absence. The main model never receives a generated summary disguised as a quotation.

The host model chooses when to call the tools, assisted by a short instruction. There is no per-turn model-based recall gate, no private-thinking interception and no replacement of the host's ordinary context.

Unindexed records remain stored and have preview cards. Oversized records can remain unindexed. Missing keywords, mistaken host decisions, finite candidates, incomplete paging and incorrect semantic grouping can all cause misses. Local raw search can recover a literal detail omitted from a card, but cannot guarantee recovery of every paraphrase. The local BM25 index is currently rebuilt from a snapshot per search; large-archive performance is unmeasured.

The native adapter captures only the user's submitted text and the final assistant message through UserPromptSubmit and Stop. It schedules indexing in a separate local process, exposes MCP search/open tools, and separates stores by canonical project path. Tool results are historical data, not current instructions.

The store is a local JSON snapshot with bounded Windows file-lock retries, not a distributed database. API keys are supplied through environment variables. Original conversations are unencrypted on disk and portions are sent to the configured inference provider.

Set `familyMode:false` for the earlier segment-only custom Worker protocol. Legacy archives remain readable, with each old segment initially treated as its own family. [EVALUATION.md](./EVALUATION.md) separates the current small family retrieval check from earlier segment-only evaluations. Long-context superiority and total token savings remain unproven.
