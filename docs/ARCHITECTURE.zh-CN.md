# 机制

正常对话完成 → 保存原文和时间 → Worker 按批次整理新增记录 → 形成不可改写的片段，并归入稳定的话题组（Topic Family）。

主模型缺少历史依据时请求工具 → 本地关键词检索及可选向量检索找候选 → Selector 阅读最多 12 个候选话题组 → 最多选择 3 组 → 必要时检查原文 → 返回原文和时间给主模型。

保存原文不调用模型，普通对话也不逐轮调用 Selector。Worker 读取新增完整记录，以及从旧目录中检索出的最多 10 个候选组，不再局限于最后 8 张旧卡片。程序检索只提供候选；“是不是同一件事”仍由 Worker 判断。候选遗漏仍可能导致重复建组。

Worker 返回短关键词卡片、逐条 `{sequence, topicIndex, change}` 分配，以及指向本批卡片或旧组的关系链接。链接区分同一事件、有关联和明确不同，必须引用对应回合原文中的逐字片段。程序核对引文来源、ID 和冲突关系，生成组标识与区间；遗漏、重复、外来回合号和空卡片会被拒绝。程序不会因为共同词语或单个“改成”就强行合并。逐字引文只能证明出处，不能单独证明语义判断正确；变更类型也不会删除旧事实。

话题卡是定位原文的短索引。Worker 尽量把持续讨论和修改放在一起，同时避免一张卡宽泛到影响定位。边界没有唯一正确答案；多拆或合并本身不自动判失败，应在固定预算下检查必需原文能否找回，以及多带回了多少内容。

固化的是已经整理的一段原文。后续讨论增加片段及组归属，旧原文、卡片和组标识不重写，不做每天一次的层层摘要。目录中的组卡片只展示首段、末段和最多两个关键词匹配片段，不能充当完整事实摘要。

本地 BM25 同时搜索旧卡片和原文，原文搜索不调用模型。可选向量仅为新卡片生成一次并保存；查询时另外生成查询向量，与关键词排名融合。这会增加建索引、查询用量和存储，不能说免费。向量失败时明确提示并回退关键词。原生插件当前默认使用关键词候选；向量由 SDK 接入者选择配置。

权重只小幅辅助相关性排序，最大影响为相关性分数的 15%。辅助分数按新近程度 60%、重复次数 30%、回合数 10% 计算并限制增长；新近程度按 30 天衰减，两个片段相隔至少 30 分钟才近似算一次重现，不因为分批就增加次数，不给总时间跨度加分。零相关不会靠“最近或聊得多”变成相关。这些数值是待验证的默认值，不代表最优或可信度。

目录和原文都有分页预算。话题组过长时，本地词语命中可让首包从相关原文开始；明确问最早/最新时优先选最早/最新的强匹配原文，前后对比问题在预算内分别读取两端。`unreadPrefix` 表示按当前读取顺序排在本页之前的原文未读；若按最新到最早读取，它们实际上更新。`memory_open` 的偏移量 0 仍能按所选顺序读取整组，`nextOffset` 可继续读后续部分。话题交错过多时，冗余的完整区间列表可以省略并标明数量；每条返回的原文仍带序号和时间。需要关联上下文时，Selector 可以在剩余名额内补充直接关联的组；遗漏的关联组会在 trace 中列出，不能称检索已完整。候选之外的组仍可翻页查找；不能把未查完说成不存在。返回的证据带原始时间，不是模型重新写出的“原话”。

原生接入通过宿主公开的消息提交和回复完成 hooks 捕获文字，通过 MCP 工具检索。它不读隐藏思考过程，也不接管宿主普通上下文。存储按项目路径隔离；完整工具轨迹、图片、旧分支编辑不在本版范围。

局限包括：主模型不一定主动检索、候选和关键词可能遗漏、语义归组可能错、大目录需要翻页、超长单条记录可能保持未索引。本地原文搜索可找回被卡片漏掉的字面细节，但不保证所有改写提问。文件存储完整读取快照，BM25 也会重新构建，大规模性能没有测定。

旧档案仍可读，旧卡片先各自作为一个组。自定义 Worker 沿用旧协议时设置 `familyMode:false`。不能从结构直接推出“最省 token”；[测试说明](./EVALUATION.md)区分了当前的小规模真实找回测试与此前不含此机制的旧实验。
